# ADR-0001: An open protocol and our own entitlement server

- **Status:** accepted; supersedes the initial spec-and-vendor-adapters direction
- **Date:** 2026-11-03

## Decision

Build OpenEntitlement as an open-source alternative for entitlement management: a shared semantic specification, OEREP remote evaluation protocol, our own server, an administrative console, and generic SDKs. This follows the separation between OpenFeature SDK providers, OFREP, and implementations such as Flipt.

The application uses one SDK API. A generic `RemoteProvider` calls our server over OEREP v1. The server owns plan values, assignments, overrides, grants, audit records, and resolution. Memory is for demos; Postgres persists entitlement data. Both SDKs may still embed a storage provider, and self-hosted installations can use a fixed provider without a service.

OEREP specifies single and bulk resolution and upgrade suggestions. Audited administration and inspection use a separate API and credentials. Usage counting, locking, and check-and-act remain in the application because application usage lives there. The protocol does not provide metering or reservations.

Core SDKs remain dependency-free. TypeScript uses fetch and Python uses urllib. Transport failures and invalid responses fail closed to local defaults. Other implementations can adopt OEREP without vendor-specific SDK adapters. The earlier Stripe Entitlements adapter packages were removed before their first release (2026-11-10): they made a billing vendor the source of entitlement values, which this decision rejects. Payment providers integrate with the service as billing adapters whose events change contracts (RFC-0001).

## Consequences

We maintain a deployable entitlement service as well as the contract and SDKs. Shared semantics and real cross-language HTTP tests keep the implementations aligned. Authentication of the transport and application tenant authorization remain separate from entitlement resolution; release flags, RBAC, payment, pricing, and invoicing remain outside the entitlement model.

Provider status events, global provider switching, and decision caching are deferred until needed. The immediate interoperability boundary is the HTTP protocol.
