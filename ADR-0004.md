# ADR-0004: Restrictive boolean install prerequisites and application-owned usage

- **Status:** accepted; supersedes direct environment-value replacement and ADR-0002's implicit unrestricted-without-Stripe statement
- **Date:** 2026-11-09

A boolean Privilege may link to an installer-owned environment prerequisite (`env_override` in the authoring model). The effective result is **entitlement AND environment**. A missing component can veto commercial access; installing it cannot grant access to a Basic customer. Integer and string environment bindings are deliberately unsupported for now. This avoids two conflicting sources of commercial values and keeps this change small.

Visibility is separate: hidden values still evaluate; read-only values use their Catalog defaults. For a read-only boolean with a prerequisite, use the default first, then AND the environment value. Bindings are visible with their source and locked in normal value controls. Missing/invalid bound settings are validation errors, not inferred permission. Workspace server-environment bindings are platform-administrator-owned; standalone Catalog bindings are installer configuration.

Billing providers translate external events into explicit entitlement facts. Payment arrangement, absent Stripe credentials or deployment location do not themselves grant rights. Quote-to-Cash is an integration flow, not a reason to add quoting, invoicing or collections to the entitlement protocol.

Applications or metering systems own usage counts, windows and idempotent consumption. OEREP evaluation is a read. A consumption dashboard can combine resolved limits with reported usage and timestamps, but missing/stale data must remain visible. Do not infer usage from evaluations, turn evaluation into a checkout/allocation, or silently create a metering ledger.

**Trade-off:** boolean prerequisites cover component availability without a generic configuration engine. More install-policy types would need a separately reviewed requirement and compatibility story. Enterprise licensing adapters must distinguish reading provisioned rights from allocating a live license.
