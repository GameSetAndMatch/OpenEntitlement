## Source evidence and delivery limits

Inspected on the `service/python` base, under `sdk-python/packages/service/src/openentitlement_service/`:

- `services/tiers.py` rejects newly selected archived fallbacks while allowing unchanged ones (Q2).
- `services/problems.py` defines validation status 400 (Q3). `main.py` requires a database unless `OE_IN_MEMORY` is true (Q4).
- `services/workspaces.py` counts all Products and lists their names on a refused downgrade (Q5, Q6).
- `services/members.py` removes Product roles on Owner promotion and membership after the last Product role is removed (Q7, Q8).
- `services/organizations.py` stores assignment status and deadlines per Product, scopes assignment permission to the Product, and validates positive integer Grants without a maximum (Q9, Q10, Q12).
- `services/catalog.py` limits environment binding changes to Platform administrators (Q11).

These are source observations, not runtime verification. OPE-42's Product evaluation is an integration preview on `service/python` ([ADR-0009](ADR-0009.md#consequences)); it is not a released contract until that branch ships. No compatibility wire fields change here.

## Q13 and Q14 follow-up

The current DELETE application-user route in `sdk-python/packages/service/src/openentitlement_service/interfaces/http/organizations.py` accepts `version` and `reason` in the query. Q13 is a small ticket: move `reason` into a typed body, update the console caller, and cover missing or blank reasons, the authenticated audit entry, stale versions and cross-Product denial with HTTP and browser regressions.

Q14 is not satisfied by documentation or automated tests.
