# ADR-0007: The Audit log is for Managers and Owners and names what changed

- **Status:** accepted; not implemented yet
- **Date:** 2026-11-12

Every Workspace member, including a User, can read the Audit log today. Each entry shows the actor's Account ID and a generic action such as `tiers:write`. Those IDs are unreadable, and showing emails instead would let Users see emails they cannot see in Members.

**Decision.** Only Managers and Owners (and Platform administrators) can read the Audit log. Under [ADR-0008](ADR-0008.md), a Product's Manager reads only the entries about their Products and their members. The service enforces this, not only the console. Entries show the actor's email.

Each entry records what it changed when the change is made: the kind of record, its ID and its name at that moment (for example "Organization Acme"). The log never reconstructs that later from the current Workspace, so an entry still reads correctly after a rename or deletion.

An entry reads as one sentence, such as "alice@acme.com changed Organization Acme's terms". It can be expanded to list only the values that changed, as before → after (Seats 10 → 20).

## Considered options

- **Everyone can read it, without emails.** Rejected because an actor's name alone is ambiguous, and the log answers "who changed this", which Users do not need to administer anything.
- **Derive the target from the stored before/after data when the log is displayed.** Rejected because it depends on the current shape of the Workspace data, and it breaks for deleted records.

## Consequences

- A User loses access to the Audit log. This is a behavior change for the Workspace preview.
