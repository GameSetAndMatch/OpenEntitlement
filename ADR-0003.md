# ADR-0003: Workspace control plane and typed Privilege Catalog

- **Status:** accepted authoring direction; partially supersedes ADR-0002's vocabulary and deployment assumptions
- **Date:** 2026-11-09

The control plane is a **Workspace**, containing a **Privilege Catalog**, Tiers, Organizations, members and audit records. An Account can create or join multiple Workspaces in one shared multi-tenant service. Organization is the entitled customer within a Workspace; Tenant remains technical isolation language rather than the preferred UI entity.

Use **Privilege** for a typed boolean, integer or string-enum entitlement value. Definitions share title, description and visibility (`hidden`, `read_only`, `editable`); a Privilege can belong to one Group and have multiple Tags. Groups may nest. This replaces Feature-first authoring in the reference console, while published OEREP v1 Feature/Plan names remain explicit compatibility concepts.

The authoring contract is validated in TypeScript and Python dataclasses without requiring a new schema framework. Defaults are inherited unless a tier/Organization supplies an allowed replacement. Missing defaults require explicit variant values; locked values require a default. The editor may author these definitions and values with backend validation and audit, rather than requiring a new released file for every edit. [RFC-0002](docs/rfcs/0002-privilege-catalog.md) records the contract and transition.

This preserves ADR-0001's protocol/provider separation. The hosted reference service is intended to be economical; no AWS-only initial deployment, particular pricing model or enterprise certification is selected by this decision. OIDC remains the workspace console identity boundary. Legacy standalone token modes remain compatibility behavior until explicitly migrated, not proof that the SaaS control plane is implemented by a shared admin token.

**Trade-off:** keeping a wire/storage adapter avoids breaking existing consumers, but requires clear terminology and tested migrations. Existing preview Feature containers become Groups without discarding metadata or entitlement values. This is accepted product direction, not a new normative OEREP version or a claim that all deployment work has shipped.
